# 小智·智家 体系架构设计文档

> 版本 v1.0 · 2026-09 · 本文档描述「小智·智家」AI 语音智能家居控制系统的完整体系设计

---

## 1. 设计目标

设计并实现一套以 **AI 语音机器人（小智）** 为核心、**主动化 / 互动性 / 智能化 / 万物互联** 为特征的完整家庭智能控制系统，覆盖：

- **感知**：语音、环境（温湿度/空气质量/光照）、人体存在、视觉
- **决策**：大模型意图理解 + MCP 工具调用 + 场景规则引擎 + 习惯学习
- **执行**：四通道控制（红外 / 433MHz / MQTT / ESP-NOW）+ 自制智能节点
- **知识**：NAS 私有云联动（日程 / 文档 / 录音 / 待办），RAG 检索增强
- **交互**：多轮语音对话、声纹识别、状态回读确认、表情屏反馈

## 3. 子系统设计

### 3.1 语音交互终端（小智终端）

**硬件**：ESP32-S3 + 双麦克风(麦克风阵列) + I2S 功放喇叭 + 1.28" 圆屏 + 灯带

**功能**：
- 离线语音唤醒（自定义唤醒词"小智小智"）
- 声纹识别：区分家庭成员，个性化响应
- 流式 ASR + LLM + TTS：低延迟多轮对话（基于 xiaozhi-esp32）
- 表情屏 UI：听、想、说、执行 四种状态动画反馈
- 网络：WiFi（WebSocket / MQTT+UDP 双协议，服务端自动优选）

### 3.2 控制中枢网关（多协议统一）

小智终端通过 **MCP 工具（设备端 MCP）** 直接控制本地外设，同时承担四种控制通道的统一调度：

| 通道 | 覆盖设备 | 接口 | 说明 |
|---|---|---|---|
| 红外 IR | 空调/电视/风扇/机顶盒 | GPIO → 红外发射管 | NEC/RAW 码库，学习式录入 |
| 433MHz | 无线插座/灯/门铃 | 射频发射模块 | 滚码/固定码插座 |
| MQTT | Home Assistant / 智能生态 | MQTT 客户端 | JSON 指令，主题订阅设备状态 |
| ESP-NOW | 自制智能节点 | ESP-NOW 广播/单播 | 低功耗、无路由器直连 |

**状态回读**：各通道执行后回读设备状态（ESP-NOW 节点回 ACK / 传感器数据；MQTT 订阅状态主题），统一上报给大模型，实现"执行 + 确认"闭环。

### 3.3 自制智能节点（ESP-NOW 从机）

基于 ESP32-C3（低成本低功耗），通过 ESP-NOW 与终端组网，无需路由器：

| 节点 | 硬件 | 功能 |
|---|---|---|
| 灯节点 | PWM 调光 + RGB 灯带 | 亮度 0-100%、色温、RGB |
| 窗帘节点 | 步进电机 + 限位 | 开/关/停/百分比 |
| 插座节点 | 继电器 + 计量芯片 | 开关 + 功率计量 |
| 传感器节点 | SHT40 + SGP40 + BH1750 | 温湿度/空气质量/光照，周期上报 |

**协议**：自定义 ESP-NOW 帧（类型 + 设备ID + 命令 + 参数 + CRC），终端统一编解码。

### 3.4 主动智能引擎

运行在终端/网关，负责"小智主动做事"：

```
事件源（传感器/时间/日程/用户行为）
   ↓ 规则引擎（when→if→then）
   ↓ 习惯学习（作息统计，异常检测）
   ↓ 主动播报（TTS 插话，降音量/暂停音乐时优先）
```

- **环境异常**：温度 > 阈值 → "厨房温度偏高，疑似忘关火"
- **作息提醒**：学习到 23:00 后入睡 → "快十一点了，早点休息"
- **日程晨报**：每天 7:30 → 播报天气+日程+通勤路况
- **久坐提醒**：结合人体传感器 + 时间 → "已经坐了一小时，起来活动一下"

### 3.5 NAS 知识中枢（nas_bridge）

在局域网部署 Python Bridge 服务，小智云端 MCP 通过 HTTP 调用：

| 能力 | NAS 接口 | 场景 |
|---|---|---|
| 日程播报 | Synology Calendar API / CalDAV | "明天上午有什么安排" |
| 文档问答 | RAG（向量检索 NAS 文档） | "上个月总结里写了什么" |
| 找文件 | File Station API | "帮我找发票文件" |
| 录音归档 | 文件写入 API | "把会议记录存到 NAS" |
| 待办管理 | Calendar/任务 API | "提醒我周五交房租" |

**数据主权**：所有个人数据留在 NAS，大模型仅作为"工具调用者"，通过 MCP 工具访问。

### 3.6 场景联动引擎

定义可组合的场景（YAML/JSON 配置）：

```yaml
场景: 睡眠模式
触发: 语音指令"执行睡眠模式" | 定时 23:00
动作:
  - 灯: 亮度 5%
  - 窗帘: 关闭
  - 空调: 26度 睡眠模式
  - 插座(卧室): 断电
  - 摄像头: 进入布防
回读确认: "睡眠模式已执行，全屋灯光已调暗，窗帘已关闭"
```

## 4. 通信与数据流

### 4.1 语音控制主链路

```
用户语音 → 唤醒 → ASR(流式) → 大模型(上下文+系统提示+工具schema)
        → 意图识别(工具调用) → MCP 执行(红外/射频/MQTT/ESP-NOW)
        → 状态回读 → TTS 确认播报
```

### 4.2 主动提醒链路

```
传感器/时钟 → 规则命中 → 主动播报任务(优先级队列)
        → 打断低优先级播放 → TTS 播报 → 恢复
```

### 4.3 MQTT 消息格式

```json
{
  "device": "living_room_light",
  "cmd": "set_brightness",
  "params": {"value": 30},
  "request_id": "a1b2c3",
  "ts": 1768500000
}
```

## 5. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 语音核心 | xiaozhi-esp32 | 成熟开源、MCP 原生支持、多芯片、离线唤醒 |
| 设备控制协议 | MCP + 四通道 | MCP 让大模型直接调用工具，四通道覆盖新旧设备 |
| 组网 | ESP-NOW（节点）/ WiFi（终端） | 节点零配置低功耗，终端走云 |
| 知识中枢 | NAS + RAG | 数据主权、隐私、个人知识库 |
| 离线降级 | 本地命令词 | 断网仍可核心控制，提升可靠性 |
| 语言 | C(固件) + Python(网关/桥) | ESP-IDF 生态 + 快速开发 |

## 6. 安全与隐私

- 个人数据（日程/文档/录音）只存本地 NAS，云端仅转发语音
- MQTT 使用账号密码 + TLS（可选）
- 声纹数据本地处理，不上传
- 网关/桥服务监听局域网，防火墙限制外网访问

## 7. 测试与验证

- **语音识别率**：不同距离/噪声下唤醒与指令识别率测试
- **控制成功率**：四通道各 100 次控制成功率统计
- **主动提醒准确率**：规则命中 vs 误报统计
- **时延**：唤醒→执行→确认 端到端时延
- **功耗**：节点待机/工作电流（µA/mA）
- **可靠性**：断网降级、节点掉线重连
